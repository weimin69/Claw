# 简历项目准备资料

这个文件夹用于把 `agent-cli-rust` 准备成一个**可讲、可防守**的简历项目。

不是让你把 1 万行代码全部背下来，而是建立：

1. 一张能随手画出的架构图；
2. 三个能讲 5 分钟的真实问题；
3. 一条能现场演示的“探索 → 修改 → 执行 → 修复”闭环；
4. 一套能诚实回答“AI 参与了多少”的说法。

## 文件说明

| 文件 | 用途 |
|---|---|
| `00-一页速览.md` | 面试前 10 分钟只看这张：30 秒介绍、架构一句话、3 个问题卡、10 个追问 |
| `01-项目答辩卡.md` | 完整版：架构图、一次请求链路、模块职责、详细问题卡、简历可写句、红线 |
| `02-仓库阅读与熟悉指南.md` | 三个晚上读完并真正理解仓库的顺序、代码入口、失败实验、自检清单 |
| `README.md` | 本文件，使用顺序和原则 |

## 建议使用顺序

1. 先读 `00-一页速览.md`，快速知道要准备什么。
2. 读 `01-项目答辩卡.md`，把讲不清的部分标出来。
3. 按 `02-仓库阅读与熟悉指南.md` 做一遍代码走读和失败实验。
4. 回来修改答辩卡，补上自己的话和真实细节。
5. 面试前只看 `00-一页速览.md`，不看代码。

## 三条原则

- **只写能解释的内容。** 简历上的每一条都要能扛住“为什么这么做”“失败了怎么办”“怎么验证”。
- **AI 参与不是原罪。** 风险在于写了讲不清的东西。被问到时如实说明参与程度，然后把话题拉回你负责的架构、调试和验收。
- **边界比功能更加分。** 能说出“目前没有 OS 沙箱、没有 token 预算、失败轮次仍会关闭会话”，比堆功能更能体现工程判断。

## 本项目当前可引用的硬事实

- 217 个确定性测试通过，模型响应由 Wiremock 模拟，不依赖真实 API。
- 工具默认只读；写操作需要 `--allow-write`，命令执行需要 `--allow-exec`。
- 模型请求 3 次尝试，1s/2s 退避，`Retry-After` 上限 30s。
- 命令默认 60s 超时，范围 1–300s；stdout/stderr 各保留 32 KiB。
- 文件读写上限 1 MiB；`read_file` 最多 500 行 / 32 KiB 正文。
- 上下文预算默认 256 KiB（内部消息 JSON 字节，不是 token）。
- 会话存档上限 16 MiB，支持 v1–v3，校验版本、workspace、消息顺序和工具 ID 配对。

> 这些数字会随代码变化。面试前用 `README` 和 `PROJECT_STATUS.md` 再核对一次。
