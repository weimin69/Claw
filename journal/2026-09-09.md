## Today's Goal

Review and improve the `fetch` command's async HTTP failure boundaries, then add deterministic CLI integration tests for `fetch`.

## What Was Completed

- Reviewed why `response.text().await` consumes `response` and why `status` must be saved first.
- Clarified the difference between `.context(...)` and `bail!(...)`.
- Updated `fetch` to use `reqwest::Client::builder()`.
- Added a 60 second timeout to `fetch` HTTP requests.
- Added error context for HTTP client construction, request sending, and response body reading.
- Changed non-2xx HTTP status handling from printing a status and returning `Ok(())` to returning an error with `bail!(...)`.
- Added `assert_cmd`, `predicates`, and `wiremock` as dev-dependencies.
- Added CLI integration tests for `fetch` success and non-success HTTP status behavior.
- Verified `cargo fmt --check`, `cargo check`, and `cargo test`.

## New Knowledge

- `response.text().await` consumes the `reqwest::Response`.
- Timeout errors happen during `.send().await`, not during client construction.
- `.context(...)` adds stage information to an existing error.
- `bail!(...)` actively creates and returns a new error.
- CLI integration tests belong in `tests/*.rs`.
- `assert_cmd` can run the compiled CLI binary from tests.
- `wiremock` can provide deterministic local HTTP responses.
- `dev-dependencies` are for test/development tools, not production runtime behavior.

## Problems Encountered

- The first `wiremock` test could not bind a local port under the default sandbox permissions.
- The first success-path test failed because the mock response body accidentally contained a newline and indentation.
- The distinction between client construction failure and request timeout needed clarification.

## Key Takeaways

- CLI commands should return non-zero exit codes when their user-facing contract fails.
- For `fetch`, a non-2xx HTTP status means the command failed to fetch usable content.
- Unit tests are better for small internal logic; integration tests are better for CLI contracts such as arguments, stdout, stderr, and exit code.
- Deterministic tests should avoid real external URLs.

## Engineering Decisions

- Treat non-2xx status codes in `fetch` as errors.
- Keep provider/body error details out of default error output for now.
- Use local mock HTTP servers for automated HTTP CLI tests.
- Put `assert_cmd`, `predicates`, and `wiremock` in `[dev-dependencies]`.
