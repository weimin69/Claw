## Objective

改善执行可观测性，补确定性代码修复综合回归，并实现显式历史会话磁盘保存。

## Changes

- 开发者报告此前连续会话手动验收通过，随后要求直接实现进度事件、综合回归与会话保存。
- `agent.rs`：增加模型和工具开始/结束事件、单调时钟耗时及失败标记；保持原有错误传播。新增已完成历史只读接口和消息 serde 支持。
- `commands/claw.rs`：stderr 显示实时进度；最终回答与统计仍在 stdout。成功回答后显式保存会话，保存失败明确报错退出。
- `tests/coding_workflow.rs`：模拟模型响应驱动真实 CLI、cargo test、读取和编辑工具，在临时项目中修复减法错误为加法；独立检查测试未改、消息历史及实际测试结果。
- `session.rs`：定义 version/workspace/messages JSON 格式；新增 SessionStore，首次不覆盖，后续检测外部改动，用临时文件写入和替换。
- `cli.rs` / `main.rs`：接入仅交互模式可用的 `--session-file`；不指定则不保存，尚无 resume 参数。
- `tests/session_storage.rs`：覆盖两轮完整存档、不启用时不落盘、工具错误历史、失败与真实 SIGINT 保留旧快照、启动拒绝已有文件和保存失败反馈。
- 保留此前已有未提交改动；未修改路线图、授权配置或 Git 历史。

## Engineering Decisions

- Runtime 发送事件，CLI 负责显示；不把进度写入模型历史，也不显示工具参数、正文或错误详情中的敏感数据。
- 综合回归验证执行链路而非模型智能；模拟模型无需 API key 或外网，真实命令使用无依赖临时项目和 cargo --offline。
- 存档与运行时 Session 分离；序列化保留用户、assistant、整批工具调用和工具结果，使用明确类型标签。
- 默认全新对话且不落盘；显式保存不等于自动加载，恢复另做。长期规则、任务摘要和向量检索与完整会话存档分开设计。
- 每次成功请求后保存完整快照；失败/取消的任务不覆盖最后成功快照。已编辑的业务文件不会随存档回滚。
- 同目录 NamedTempFile 写入后 sync_all，首次 persist_noclobber，后续内容核对再替换；Unix 模式 0600。父目录必须存在，不接受已有存档作为新会话目标。
- 序列化和保存通过 spawn_blocking 执行，当前会话仍等待保存完成；同步磁盘操作没有变快，也不具备自动取消或回滚能力。

## Issues

- 只有保存，没有加载/恢复、格式版本检查、消息合法性恢复校验或上下文长度控制。
- 会话包含源码和工具输出；无凭据字段不代表历史不敏感，当前没有自动脱敏。
- 存档外部改动检查仍存在检查/使用竞态；没有目录 fsync，不保证断电持久性；没有 OS 沙箱。
- 保存开始后不能仅靠取消 Future 停止阻塞线程；任务取消、文件操作和回滚仍需区分。
- 实时进度能定位等待阶段，但并未确定真实 provider 慢响应的具体原因；流式输出未实现。
- 新增存档能力尚无开发者手动验收记录；变更尚未提交。
