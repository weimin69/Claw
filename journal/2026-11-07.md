# 2026-11-07

## Objective

实现会话级失败恢复：失败或取消时回滚本轮对话，保持交互会话可继续；只有内部不变量错误才关闭会话。这是后续逐命令审批与 TUI 的硬前提。基线确认 217 个测试全绿。

## Changes

- `src/agent.rs`：
  - 新增 `TurnCheckpoint`（`full_history_len` + 回合开始前的 `working_context` 快照），`AgentSession` 持有 `pending_turn`。
  - `run_turn` 成功时提交上下文并清除检查点；失败时 `fail_turn()` 截断 `full_history`、恢复 `working_context`。
  - 新增幂等 `abort_turn()`，供被 `tokio::select!` drop 的取消路径还原内存状态。
  - 新增私有 `SessionInvariant` 标记：迭代计数溢出、工具批次计数溢出、单工具次数溢出、上下文序列化失败。只有这类错误保持 `closed = true`。
  - `ContextLimitExceeded` 新增 `ContextLimitStage::{Input, TurnInProgress}`；`check_context_size` 增加 stage 参数。
- `src/commands/claw.rs`：
  - 交互模式可恢复失败后打印“本轮失败，会话已回滚到上一轮，可以继续输入”，不退出；`!can_continue()` 才返回错误。
  - 两种上下文超限分别保留“本次输入未发送”和“工具执行后上下文超限”提示；后者改为回滚并继续。
  - Ctrl+C 分支先 `abort_turn()` 再返回 `Cancelled`（仍退出 130）。
- 测试：
  - 单元测试改写旧的“失败即关闭”断言，新增工具后模型失败回滚、致命工具错误后重试、回合中超限回滚、不变量关闭、`abort_turn` 幂等与分类测试。
  - 集成测试改写 4 个：交互模型失败后接受下一条输入、回合中超限回滚且恢复存档不变、恢复会话失败不覆盖存档、失败轮不落盘且下一轮正常保存。
- `README`、`SESSIONS.md`：更新上下文超限、执行统计与失败语义，删除“失败后会话不可复用”。

## Engineering Decisions

- 检查点放在 `AgentSession` 而不是 `run_turn` 的局部变量：取消会 drop future，函数内的清理不会执行；会话持有快照后，`abort_turn` 可在未来任何位置恢复。
- 回滚恢复到回合开始快照（裁剪前），下一轮重新执行裁剪，保证工作的上下文仍是完整轮次边界；代价是可能重复打印裁剪提示。
- 错误分类用私有 marker 类型加 anyhow context 链（`error.is::<SessionInvariant>()`），不引入公开错误枚举，`run_turn` 签名不变。
- `ContextLimitStage` 只影响 CLI 提示，不改变 Runtime 的失败可恢复性；输入前超限仍不写入任何历史。
- “对话回滚、磁盘不回滚”：文件写入与命令副作用保留，失败轮不输出统计，提示中明确说明。
- Ctrl+C 保持退出 130 的既有契约；`abort_turn` 先保证内存一致，并把“取消本轮后留在会话”留给 TUI 阶段决定。

## Issues

- 失败轮若已触发上下文裁剪，回滚到裁剪前快照后，下一轮会再次提示裁剪。
- 失败轮已产生的 effects 不进入统计，用户只能从提示得知文件与命令不会回滚。
- 内部不变量错误（计数溢出、序列化失败）无法端到端触发，只有分类单元测试。
- Ctrl+C 仍直接退出；取消后继续输入尚无 CLI 交互。
- `.DS_Store` 的工作区改动早于本次工作，未纳入本次提交内容。
