## New Knowledge

- Agent 与一次性 chat 的核心差异是运行循环和状态转换，而不是更复杂的 prompt。
- `pub(crate)` 允许 crate 内共享类型，但不承诺对外公开 API。
- 运行上下文需要保存消息语义和来源，不能只保存无类型字符串。
- `iteration` 表示已经调用模型的次数；第 `max_iterations` 次调用合法，下一次开始前失败。
- trait 可以让 Agent Loop 依赖行为边界，而不依赖 FakeModel 或具体 Provider 类型。
- `&[AgentMessage]` 让模型只读借用上下文，不取得所有权。
- `&mut self` 允许 FakeModel 消费预设决策，也允许实现记录调用状态。
- `VecDeque::pop_front()` 适合按 FIFO 顺序返回预设模型决策。
- 泛型 `M: AgentModel` 让同一个 `run_agent` 使用不同模型实现，而无需现在引入 trait object。

## Problems Encountered

- 多次修改类型时出现文件未保存、遗漏 `pub(crate)` 和字段单双数命名反转。
- 最初只用 `is_empty()` 校验 prompt，遗漏全空白输入。
- 构造测试误把整个 `AgentState` 当作单条消息，并重复消费同一个 `Result`。
- `begin_iteration()` 最初硬编码数值 3，破坏调用者提供的最大迭代上限。
- 测试中误用 `.context()` 代替错误信息断言。
- `run_agent()` 最初被放入 `#[cfg(test)]` 模块，导致正式构建不可用。
- `AgentState::new()` 返回 `Result`，最初没有使用 `?` 解包。
- 最终回答测试最初直接调用 FakeModel，没有覆盖完整 `run_agent` 链路。
- 当前 Agent Runtime 尚未接入 CLI，因此普通构建仍存在 dead-code 警告。

## Key Takeaways

- Runtime 自己必须维护状态不变量，不能只依赖 CLI 提前校验。
- 迭代限制应在模型调用前检查，保证上限语义清楚且失败不破坏状态。
- FakeModel 应返回结构化决策，而不是模拟模糊自然语言。
- 测试 Agent Loop 应调用 Runtime 入口，而不是只重复测试 fake 组件。
- Agent 编排、模型决策和工具执行是不同职责，需要明确边界。
- 学习阶段先建立最小可测试闭环，再接入真实 HTTP Provider 和复杂工具系统。

## Engineering Decisions

- 第一版 Agent 状态使用单文件 `agent.rs`，暂不创建大型目录结构。
- `ModelDecision` 第一版只支持最终回答和单个工具调用。
- `AgentMessage` 第一版不引入 tool call ID；并发多工具时再评估。
- 使用泛型 `AgentModel`，暂不引入 `Box<dyn AgentModel>` 或通用 Provider trait。
- FakeModel 只存在于测试模块，不进入生产代码。
- 第一版 `run_agent()` 当前仅完成 FinalAnswer 路径；ToolCall 明确返回未实现错误。
- 定义独立 `ToolExecutor` 边界，避免把具体工具逻辑写进 Agent Loop。
