## New Knowledge

- `anyhow::Context` 的作用是给已有错误补充发生位置和业务语义，而不是主动创建错误
- `bail!` 用于主动创建并返回错误，和 `.context(...)?` 的用途不同
- `reqwest::Client::builder()` 适合配置 timeout 等 client 行为
- `std::time::Duration::from_secs(60)` 可以表达 60 秒时间长度
- `Response::text()` 会消费 `response`，调用后不能再使用原来的 `response`
- 超时不是为了让请求变快，而是为了给失败设置明确边界

## Key Takeaways

- 错误处理是工程边界设计的一部分，不只是让程序退出
- async HTTP 请求应该把失败拆成清晰阶段：构造 client、发送请求、读取 body、检查 status、解析 JSON
- 用户默认需要简洁、安全的错误信息；开发者调试时需要通过错误链或未来的 verbose/logging 看到更底层的信息
- 当前 CLI 单次 `chat` 创建一个 client 可以接受，未来 Agent runtime 多轮 LLM 调用时再认真考虑 client 复用

## Engineering Decisions

- 当前为 `chat` 请求加入写死的 60 秒 timeout，不先引入配置项或 CLI 参数
- 当前不重构 `reqwest::Client` 复用，避免在 Agent runtime 之前提前引入架构复杂度
- 当前非 2xx status 默认只输出 status，不直接暴露 provider 错误 body
- 当前继续保持 `src/openai.rs` 的模块名，暂不重命名为 `llm`
