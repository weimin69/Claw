# 2026-10-17

## Objective

完善 Agent 执行控制，并接入 workspace、目录探索、文件读取和代码搜索，形成可验证的仓库理解能力。

## Changes

- `agent.rs`：新增工具调用累计预算、批次执行前检查和溢出检查；轮数与工具次数均改为可选预算，无预算时不因次数停止。
- `cli.rs`、`commands/claw.rs`、`main.rs`：接通可选预算、`--workspace`（默认 `.`）和 Ctrl+C 取消；取消输出到 stderr，退出码为 130。
- `Cargo.toml` / `Cargo.lock`：启用 Tokio signal 支持及相应依赖。
- `config.rs`：开发者修复嵌套 if 的既有 Clippy 警告。
- 新增 `workspace.rs`：验证根目录、解析真实路径，并拒绝 workspace 外的现有目标，包括外部符号链接。
- `tools.rs`：执行器持有 Workspace；实现 `list_files` 和 `read_file`；文件系统操作使用 `spawn_blocking`。
- 新增 `tools/search.rs`：实现大小写敏感的字面代码搜索，返回相对路径、行号和匹配文本。
- `openai_compatible.rs`：向模型声明三个仓库工具的参数、用途和限制。
- 扩展单元测试与 `claw_cli.rs`，覆盖预算、取消、workspace 校验和三个工具的模型—工具—模型闭环。

## Engineering Decisions

- 取消默认 8 轮与硬编码 32 次限制；用户按任务显式指定预算，默认持续运行至最终回答、用户取消或致命错误。
- 工具预算在整批执行前检查，拒绝超限批次；预算恰好用完后仍允许模型返回最终答案。
- Workspace 以启动目录为默认起点；工具执行器持有根目录，不修改进程工作目录。
- `list_files` 只列直接子项，按路径排序，最多 200 项；子目录由模型继续调用探索。
- `read_file` 支持 1-based inclusive 行范围，默认 200 行，最多 500 行及 32 KiB 内容；仅接受最大 1 MiB 的 UTF-8 普通文件，拒绝 NUL 内容。
- `search_code` 递归搜索指定文件或目录；遍历跳过符号链接、`.git` 和 `target`；上限为 5000 个目录条目、8 MiB 实际扫描、单文件 1 MiB、100 条匹配和 32 KiB JSON 输出。长行片段最多 1024 字节；通过 `truncated`、`skipped_files` 和 `line_truncated` 表达不完整结果。
- 暂不引入正则、索引或通用工具框架。搜索实现单独拆到 `tools/search.rs`，避免继续扩大单文件。
- 下一阶段编辑能力尚未实施；已有文件精确替换只是候选方案，不能视为已确定的完整 patch 协议。

## Issues

- 调试闭环测试时发现 mock 请求部分匹配覆盖了后续轮次，已增加轮次区分；搜索结果 JSON 字段顺序导致字符串断言失败，已改为解析后按 JSON 内容比较。
- Workspace 是应用层路径检查，不能防止检查后路径被其他进程替换；不是系统级沙箱。
- Ctrl+C 取消当前 Agent Future，但不覆盖同步 stdin 读取，也不能立即停止已经启动的 `spawn_blocking` 工作；尚无外部进程管理。
- 未设置预算时，没有自动的循环次数或任务总时长上限，依赖用户取消或模型停止；无人值守运行应显式设置预算。
- 搜索不支持 `.gitignore`，跳过的二进制、编码无效和超大文件会计数；遍历达到条目上限后的结果属于部分扫描。
- `list_files` 限条目数但没有总 JSON 字节上限；`read_file` 的 32 KiB 限制针对正文，JSON 编码后会增加体积。
- 文件工具尚无敏感路径排除规则或工具执行跟踪输出。
- 本次实现尚未提交；保留所有现有工作区修改，没有修改本地凭据内容。
