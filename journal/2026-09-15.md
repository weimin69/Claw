## New Knowledge

- `wiremock` 的核心价值是让测试确定、快速、可重复，不依赖真实网络、真实 API key、provider 可用性、余额、限流或模型行为变化。
- CLI 集成测试主要验证本项目的用户契约，包括请求路径、请求体、stdout、stderr 和 exit code，而不是测试第三方 provider。
- `chat.rs` 是命令层，负责把 CLI 参数连接到配置加载、LLM 调用和最终输出。
- `config.rs` 负责配置模型、默认值、TOML 解析和业务校验。
- `openai.rs` 负责 OpenAI-compatible HTTP 请求、status 判断、response body 读取和 JSON 响应解析。
- stdout / stderr 分离是 CLI 工程里的重要契约：成功结果进入 stdout，错误信息进入 stderr。

## Key Takeaways

- 自动化测试不应该直接依赖真实 LLM API；真实 provider 属于外部系统，不应该成为日常测试是否稳定的前提。
- 模块边界不是为了拆文件而拆文件，而是为了让配置、命令执行、HTTP provider 通信可以分别理解、测试和演进。
- 失败路径下 stdout 为空不是细节洁癖，而是在保护脚本调用者不会误消费错误结果。
