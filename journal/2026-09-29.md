## New Knowledge

- `ModelDecision` 表示模型本轮决定，`AgentMessage` 表示提供给模型的历史上下文。
- `AgentModel` 与 `ToolExecutor` 是两个独立行为边界，`run_agent()` 负责协调它们。
- `&str` 适合临时借用输入；需要跨方法保存的数据应转换为 owned `String`。
- `&mut self` 由方法调用语法自动传入，接收者变量必须声明为 `mut`。
- `.await` 后得到 `Result<String>`，`.unwrap()` 后得到内部的 `String`。
- 保存消息快照需要克隆借用切片，因此为 `AgentMessage` 派生 `Clone` 并使用 `messages.to_vec()`。
- Rust 枚举变体通常通过 `Enum::Variant` 访问，字符串转换应发生在构造枚举之前。

## Problems Encountered

- 一度把 trait 实现写成 `impl FakeToolExecutor for FakeToolExecutor`，混淆了 trait 与具体类型的位置。
- 一度把 `received_messages` 错当成 `FakeModel::new()` 的调用参数；Rust 函数调用不支持这种命名参数写法。
- 在嵌套测试数据中省略了 `AgentMessage::`，并把 `.to_string()` 错误地应用到整个枚举值上。
- 在错误路径测试中误把 `Result<String>` 当作保存调用记录和消息历史的对象。
- 多次因格式未保存导致 `cargo fmt --check` 在测试前退出。

## Key Takeaways

- Agent Runtime 的核心不是一次模型请求，而是“模型决策、工具执行、更新上下文、再次决策”的循环。
- 测试替身不仅要提供可控输出，还要记录调用和输入，才能验证交互是否正确。
- 最大迭代次数限制的是模型决策轮数；第一轮工具执行完成后，第二轮模型调用仍可能因上限而被拒绝。
- 测试应检查正确对象：最终结果在 `Result` 中，工具调用记录在 executor 中，模型输入快照在 model 中。

## Engineering Decisions

- 当前继续使用泛型 `M: AgentModel` 和 `T: ToolExecutor`，暂不引入 trait object。
- 第一版 Agent Loop 保持单工具顺序执行，不引入并发、tool call ID 或工具注册表。
- 工具成功后按 `ToolCall`、`ToolResult` 的顺序写入上下文。
- 使用 FakeModel 和 FakeToolExecutor 做确定性测试，不依赖真实模型或真实工具。
