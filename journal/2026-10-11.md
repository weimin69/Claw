## New Knowledge

- 源文件存在并不代表它自动进入 Rust 模块树；需要通过 `mod` 声明注册。
- `.await` 先把 Future 驱动到输出，之后 `?` 才能处理得到的 `Result`。
- `tokio::time::sleep().await` 暂停当前 Task，但不会在等待期间占用 worker thread。
- 错误上下文应补充业务语义，同时保留底层原因。
- 环境变量 fallback 与 override 不同；当前 API key 优先级是非空 TOML、非空环境变量、空字符串。

## Problems Encountered

- 一开始把 `main()` 描述成“错误分发”，没有准确区分命令分发与进程级错误处理。
- 一开始认为异步等待仍会占用 Tokio worker thread，需要继续巩固 Task 与线程的区别。
- 一开始误判环境变量会覆盖 TOML API key，需要继续巩固 fallback 的控制流。
- 对丢弃底层错误所损失的诊断信息，以及 `Option<String>` 表达缺失状态的原因，需要提示后才能说明。

## Key Takeaways

- `run()` 负责解析和命令分发，命令 `execute()` 负责命令行为，`main()` 负责进程级错误展示与退出码。
- `?` 只从当前函数提前返回错误，不负责打印错误或直接终止进程。
- 异步等待暂停的是当前 Task；worker thread 可以继续运行其他已就绪的 Task。
- 配置处理应区分读取失败、解析失败和业务校验失败。
- 外部状态读取与纯合并规则分离，可以降低并行测试互相干扰的风险。

## Engineering Decisions

- 保持当前命令模块负责用户输出、`run()` 只负责分发的项目约定。
- 保持底层函数返回 `Result`，只在最外层 `main()` 决定打印错误和退出进程。
- 保持显式 TOML API key 优先、环境变量只作为回退值。
- 当前一次性 CLI 继续允许同步读取 stdin；交互式 Agent Runtime 阶段再评估异步 stdin。
