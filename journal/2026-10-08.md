- 为 BuiltinToolExecutor 增加 `add` 分发测试和未知工具错误测试。
- 使用 FakeModel 与真实 BuiltinToolExecutor 跑通确定性 Agent Loop。
- Agent 模块当前 11 个测试通过，工具模块当前 6 个测试通过。
- 为 ToolCall 与 ToolResult 增加关联 ID，防止同名工具调用结果串线。
- 提交关联 ID 数据模型升级：`feat: add tool call correlation ids`。
- 根据官方 OpenAI Function Calling 协议核对 tool call 与 tool result 字段。

- 定义 ChatToolCall 与 ChatFunctionCall 协议 DTO。
- 实现 AgentMessage 到 user、assistant tool_calls、tool 三类协议消息的纯映射。
- 新增映射序列化测试；当前 OpenAI-compatible 模块 8 个测试通过。

## New Knowledge

- FakeModel 控制模型决定，真实 Runtime、AgentState、BuiltinToolExecutor 和工具逻辑仍会在确定性测试中运行。
- `tool_call_id` 是调用与结果之间的关联键，工具名称不能替代它。
- 编译器驱动重构可以准确列出枚举字段变化影响的所有位置。
- `#[serde(tag = "role")]` 可以把 Rust enum 序列化成按角色区分的协议消息。
- `#[serde(rename = "type")]` 可以让 Rust 字段名与外部 JSON 协议字段解耦。
- `iter().map(...).collect()` 可以把借用的 Runtime 消息转换成 owned 协议 DTO。

## Problems Encountered

- 第一次真实执行器 Agent 测试被误写进另一个测试函数内部。
- FakeModel 最初只准备了 ToolCall，没有准备第二轮 FinalAnswer。
- 测试 prompt 与预期 User 消息不一致。
- 调用异步 `run_agent()` 时一度遗漏 `.await.unwrap()`。
- 关联 ID 重构后，多处测试 fixture 缺少 `id` 或 `tool_call_id`，通过编译器逐项修复。
- 多次在未运行 rustfmt 时触发格式检查失败。

## Key Takeaways

- 同名工具可以被调用多次，必须使用调用 ID 保证结果关联正确。
- Provider 协议消息与内部 AgentMessage 职责不同，需要显式适配层，不能直接复用一种结构。
- ToolCall 必须序列化为 assistant 的 `tool_calls`，ToolResult 必须使用相同 `tool_call_id`。
- 真实 LLM 不适合作为 Runtime 单元测试依赖；FakeModel 能稳定、低成本地控制多轮行为。

## Engineering Decisions

- Runtime 内部保留工具名称用于调试；发送 ToolResult 时只映射协议要求的 ID 和内容。
- 当前一次 AgentMessage::ToolCall 映射为一个长度为 1 的 tool_calls 数组，暂不支持单轮多工具调用。
- ChatMessage 使用 enum 表达不同角色的合法字段组合，避免大量可选字段形成非法状态。
- 在 HTTP 和真实模型适配前，先以纯函数和 JSON 序列化测试固定协议契约。
