# 2026-11-01

## Objective

补齐 Phase 5.4 Completion Reporting 的缺口：每轮结束后，用户能独立核对实际改动的文件与执行过的命令，而不是只看到工具调用次数和模型自述。实现采用“工具声明副作用 → Runtime 按序收集 → CLI 聚合展示”的结构。

## Changes

- `src/agent.rs`：新增 `ToolEffect`（`CreatedFile`、`ModifiedFile`、`CommandFinished`）；`ToolOutput` 增加 `effects`；`AgentRunResult` 增加有序 `effects`；`run_turn_loop` 在工具结果返回后收集效果。新增测试验证效果保留顺序与重复，且不进入模型消息。
- `src/tools.rs`：新增成功载荷 `ToolResult { content, effects }`；分发处统一转换为 `ToolOutput`；只读工具继续返回 `String`。
- `src/tools/edit.rs`：批量 edits 数量在准备阶段取出；`apply_edit` 成功后产生 `ModifiedFile`。
- `src/tools/create.rs`：`persist_noclobber` 成功后产生 `CreatedFile`。
- `src/tools/command.rs`：进程启动后产生 `CommandFinished`，无论成功、非零退出还是超时；spawn 失败不产生效果。
- `src/commands/claw.rs`：新增 `format_effects()` / `format_command()`；`print_result` 依次输出变更文件、执行命令、工具统计。路径与命令做 `escape_debug`，命令行截断到 160 字符。新增格式单元测试。
- `tests/claw_cli.rs`：新增 `create_file` 摘要集成测试；更新两处精确 stdout 断言。
- `tests/coding_workflow.rs`：单文件与双文件修复场景增加文件路径、修改处数与退出码断言。
- `SESSIONS.md`：补充执行统计的组成、效果不发送给模型/不写入存档、`run_command` 内部写入不可见。

## Engineering Decisions

- 效果只由工具的成功落盘点或进程启动点产生，Runtime 不解析工具 JSON 反推，避免把失败调用误报为变更。
- 命令效果与 `is_error` 解耦：`exit 101` 代表测试执行了但失败，必须出现在摘要中。
- 效果不进入 `AgentMessage::ToolResult`，因此不发给模型、不参与上下文预算、不改变 v1–v3 存档格式。
- Runtime 保留有序且可重复的原始事实，去重与合并只在 CLI 展示层；原始向量留给后续 trace 与评估统计。
- 命令行展示有界并转义控制字符，避免模型提供的参数破坏终端输出。

## Issues

- `run_command` 内部产生的文件改动无法列出，摘要只能显示命令与退出状态，此项需在文档和后续设计中保持诚实。
- 失败或取消的请求不打印统计（沿用既有行为），效果随内存丢弃。
- 效果未持久化，尚不能作为可回放的执行追踪。
- `README` 仍停留在早期状态，声称 Agent Runtime 未接入 CLI，与当前实现不符。
